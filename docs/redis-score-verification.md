## 实测环境与隔离

- Redis 7.2.6，从官方 release 下载，源码 SHA256 与 [redis/redis-hashes](https://github.com/redis/redis-hashes/blob/master/README) 一致：`fb10d67a2fe2b4556f6cb840064dd6e6e3175ce8ca035f0726990ec2da9f3d0e`。此版本仅用于可复现测试，不是生产升级建议。
- 本机临时编译，不安装系统服务；测试自行创建 `/tmp/mjr-*` 数据目录和 Unix socket，TCP 端口为 0，权限 700；不读取 `REDIS_URL`，不接受外部 Redis 地址。
- 耐久性组：`appendonly yes`、`appendfsync always`；对照组：默认 RDB、`appendonly no`。
- 故障注入只作用于测试自己的应用子进程和 Redis 子进程；真实 Socket.IO 使用临时本机端口。退出后关闭客户端/子进程并删除测试数据目录，最终检查没有残留 `/tmp/mjr-*`。

真实 Redis 专项覆盖：

- 提交命令执行前失败：仍是原局面且无新历史，重试可完成。
- 应用在提交前被 SIGKILL：无半个终局，恢复后重试计分一次。
- 应用在提交后、返回前被 SIGKILL：快照和历史均存在，恢复补记不重复。
- Redis 实际执行成功但客户端丢失确认：重连及重试保持一次结算。
- 24 个并发历史写入跨两条连接：只追加一条；冲突记录拒绝，原值与 TTL 正确。
- 胡牌与断线并发，以及带非零起始基线的“最后弃牌触发首牌罚分 + 流局”与断线并发：分数、断线标志、日志一致。
- 过期玩家、过期局号、过期 turnCount 的超时不改变局面。
- Redis SIGKILL + AOF 重启：已确认的积分与基线保留，恢复不重复。
- 进程重启只一位玩家重连：其他三位保持离线，不错误续局。
- 开局提交失败后可重试；关闭房间补日志失败时仍保留恢复机会。
- 默认 RDB 对照组：写入并确认一条罚分流局记录，在生成快照前 SIGKILL，重启后该条记录与局面不存在。**这一项测试通过意味着正确复现了风险，不意味着默认部署通过耐久性验收。**
- 真实 Socket.IO：第 7 局重连不会变成第 1 局，重复广播只续局一次，历史补齐；替补继承基线与补杠来源，解散后不再列入恢复集合。

## 可复现命令

先准备一个本机 `redis-server` 可执行文件，再在仓库根目录执行：

```bash
MJ_REDIS_SERVER=/absolute/path/to/redis-server npm run test:redis
```

脚本没有默认外部 Redis 地址，未提供可执行文件会失败。测试需要允许启动本机进程、Unix socket 和临时 Socket.IO 监听端口。不会访问已有 Redis 数据库；测试里的清空命令仅针对该次自行启动的实例。

## 发布前持久化迁移方案（生产尚未执行）

隔离演练结果和分阶段命令、配置文件与 compose 的区别、检查点与回滚边界见 [迁移运行手册](redis-migration-runbook.md)。四项新增测试已通过，包含 RDB/AOF 冷恢复、迁移后新增局强制重启、错误迁移顺序对照。备份恢复逐项比较局号、基线、delta/total、房间登记和绝对过期时间；不是只检查能否启动。

1. 在经授权的运维窗口核对实际 Redis 版本、持久化参数、数据卷及完整备份；本次只确认仓库配置，未核对生产实际参数。先用备份副本在隔离环境验证恢复。
2. 本项目没有维护模式；在窗口安排结束游戏后停止应用写入，核实未完成局并保留其快照，导出房间/局号/四家累计分与 delta 的校验清单。保留 RDB 备份及独立长期归档。
3. 对已有 RDB 数据应在运行中的 Redis 上启用 AOF 并等待初始重写完成，再持久化相同启动配置；不要只修改 compose 然后直接重启。核验 `aof_rewrite_in_progress=0`、`aof_rewrite_scheduled=0`、`aof_last_bgrewrite_status=ok`。
4. 对“不丢失已确认积分”的目标，评估 `appendfsync always` 的写入延迟和存储容量；若选择 `everysec`，必须明确接受故障时可能丢失约一秒数据。此处没有替用户改动生产性能/耐久性取舍。
5. 在备份副本上重启并核对关键房间、日志条数、每局 delta 与累计分连续性；演练成功并批准后才安排生产发布。从修复版本的新房间开始采集，7 天过期前独立归档。

迁移顺序及 fsync 取舍参见 [Redis 官方持久化文档](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)。该文档特别要求已有 RDB 数据先在线转换为 AOF；单纯改配置重启有数据丢失风险。

## 本轮边界

- 同房间顺序队列限定为单 GameController / 单服务实例；独立 Redis 连接的日志去重已测，不等于支持多实例同时推进同一局。
- 本机 AOF + SIGKILL 测试不代表已覆盖主机断电、磁盘损坏、磁盘写满、Redis 主从切换或集群。生产当前耐久性策略仍待核查/审批。
- 旧错误积分日志仍不自动重写；缺少可信基线时拒绝猜测。替补局、未完成解散局仍应单独处理。
- 房间日志仍保留 7 天。本轮未实现长期归档服务或训练软件。
